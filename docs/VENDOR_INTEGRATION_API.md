# Vendor Integration API

## Purpose

The Vendor Integration API is a controlled read-only foundation for external vendor integration providers. It allows a provider to pull only the orders allocated to the vendor attached to its token.

This API does not create shipments, invoices, payout records, accounting entries, returns, refunds, or Shopify mutations.

## Authentication

Requests must use a bearer token:

```http
Authorization: Bearer spg_vi_...
```

Tokens are generated by Sporgym and printed once:

```bash
npm run vendor-integration:create-token -- --vendorIdentifier=sporjinal --providerName="Provider Name" --scopes=orders:read
```

Operational rules:

- Store the plaintext token only in the provider's secret store.
- Sporgym stores only a token hash.
- Tokens can be disabled or revoked.
- Disabled or revoked tokens are rejected.
- Requests are scoped to the token's `vendorIdentifier`.

## Scopes

Initial supported scope:

- `orders:read` - allows reading allocated orders for the authenticated vendor only.

Write scopes are intentionally not modeled yet.

## Endpoint

### `GET /api/vendor-integration/orders`

Returns VendorAllocations for the authenticated token's vendor.

Query parameters:

- `status` - optional allocation status filter, for example `ACTIVE`.
- `limit` - optional page size, default `50`, maximum `100`.
- `cursor` - optional cursor from the previous response.

Example:

```bash
curl \
  -H "Authorization: Bearer spg_vi_..." \
  "https://backend.example.com/api/vendor-integration/orders?limit=50"
```

## Security Rules

- The API never accepts a vendor identifier from the request body or query string.
- Vendor scope is derived only from the authenticated integration token.
- The endpoint filters `VendorAllocation.assignedVendorId` to the token vendor.
- Audit logs store method, path, status code, request id, client id, vendor identifier, and timestamp.
- Audit logs do not store full request bodies, response bodies, tokens, passwords, or provider secrets.
- Invalid tokens are rejected before any order query is executed.

## Future Direction

Future provider integration phases may add shipment status, invoice references, or fulfillment updates after a separate security and operational review. Those write endpoints are not part of this foundation.
